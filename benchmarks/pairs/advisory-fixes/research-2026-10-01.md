# Advisory-fix pairs: research log (2026-10-01)

Purpose: give the learned decision engine defensible negatives for the families that had none or few (repository
groups with a fixed-side negative before this: untrusted_destination 8, path 3, output_encoding 1, deserialization 0,
access_control 0; commit 658f2d5 dropped 108 invented negatives). A pair is a public fix commit for a published
advisory (CVE/GHSA), distinct from its parent, where the advisory-named function is declared on both sides and its
body changes. The positive is the function at the parent, the negative the same function at the fix.

## Method

- **Enumeration.** One lane per family worked the GitHub advisory database (`gh api /advisories?ecosystem=<eco>&cwes=<n>`)
  per ecosystem (pip, npm, maven, composer, go, rubygems, nuget), newest first, with web search only to locate a fix
  commit an advisory did not link. The family is the advisory's CWE through `ruleset/families.toml`.
- **Exclusions before examination.** Every repository already named under `benchmarks/` (its github.com URL or a
  catalog `repo =`, collected with the reserved-population files excluded by name and never opened) and every
  repository already claimed by another lane: one pair per repository across the whole catalog.
- **Metadata only.** Advisories, commits, file lists, repository size and licence came from `gh api`. The two versions of
  the one vulnerable file were read through `materialize.py --candidate`: a shallow blobless fetch
  (`--filter=blob:none`, depth 2) into the pair cache and `git show <sha>:<path>`. No scanner, rule, engine, plane task
  or model ran on any of these repositories. Repositories over ~150 MB (`size` > 150000 KB) were rejected unread.
- **Acceptance.** The checker cuts the function on both sides with the label builder's own matcher
  (`learn.excerpt.function_bounds`) and accepts only when both sides declare it and its body (lines after the
  declaration, whitespace-normalised) differs. Fixes in large release/squash commits, fixes outside any function
  (route tables, config, templates), functions deleted or renamed by the fix and family mismatches were rejected.
- **Reserved population.** After the catalog was written, `tests/test_independent_population.py::
  test_no_reserved_repository_is_referenced_by_the_development_tree` flagged five accepted repositories (2 path,
  1 deserialization, 2 access_control). They were dropped; their rows below are kept as rejections with the name and
  advisory withheld, and their cache entries deleted. Two rejected rows (one output_encoding, one deserialization)
  also named reserved repositories; their names and ids are withheld the same way (the lane tallies below keep their
  original rejection reasons).
- **Licences.** SPDX id from the API; where the API said NOASSERTION the LICENSE file name/text was read through the API
  (rack MIT, handlebars.java Apache-2.0, omnifaces Apache-2.0, og-image MIT, django-cms
  BSD-3-Clause, C1 CMS MPL-1.1). Permissive licences were preferred; 7 accepted pairs are copyleft (GPL/AGPL/LGPL/MPL),
  used where too few permissive candidates in a language qualified.

## Known limits

- The function matcher is the label builder's, so excerpts inherit its limits: for `htmlsanitizer-dosanitize-0ac53dc`
  (C#) the span runs to the end of the class and for `zeppelin-fromjson-8368579` (Java) it takes in the next method.
  Both functions' own bodies change; the label is `path::function`, unaffected.
- Multi-commit fixes use the commit before the first fix commit as `parent` (LiteDB); merge-commit fixes use the
  first parent (truelayer-dotnet, weasyprint, oqtane, jellyfin and others noted in their rows).
- jellyfin's advisory (GHSA-4vx8-xhc9-qg6x) is a repository advisory not in the global database.
