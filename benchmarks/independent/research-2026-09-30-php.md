# Independent evaluation population v3 (PHP): candidate real-world cases

Research date: 2026-09-30. Method: web research only. I read GitHub advisory records (the global advisory API, reviewed and unreviewed), commit pages, compare views, repository metadata and file histories through `gh api` (read-only) and GitHub search. I did not clone, download or check out any candidate repository, did not run any scanner, rule, engine or project tool on one, and did not read candidate source beyond what an advisory itself quotes. Commit pages were read for their metadata (parents, message, changed-file names and line counts), not their patch text.

Output: this file and `candidates-v3-php.json` (26 candidates, machine-readable, one record per case in the v2 schema plus research fields). Nothing is reserved yet: the maintainer chooses, then a `population-v3.toml` and a protocol are written and frozen as for v2.

## Why a v3, and what it must not contain

PHP quick-mode rules were written on 2026-09-30 while looking at PMPro, population-v1's PHP cases, Ultimate Member, MediaWiki and WP Statistics. None of today's PHP numbers qualifies, and population v2 is reserved for other qualification. v3 must be PHP cases nobody in this project has looked at.

## Selection criteria (fixed before looking at any advisory)

From the maintainer's brief, unchanged:
- **Language** PHP. WordPress plugins allowed but capped at half the population; non-WordPress PHP applications and frameworks included.
- **Recency**: advisory published 2026-06-01 or later, taken newest first; a public fix commit or tag diff in a public GitHub repository; identifiable vulnerable and fixed versions.
- **Family spread**: at most about 40% injection; include output_encoding, path, untrusted_destination, deserialization, access_control and OS command injection where advisories exist. Families are the ids of `src/openultrasast/ruleset/families.toml`, and an advisory's family is found from its CWE ids through that file's `cwes` lists (so CWE-434 upload and CWE-74 generic injection map to no family).
- **Declarable site**: the advisory names the vulnerable function or file, so a `sites` entry can be declared from its text alone.
- **Exclusions**: any repository whose `github.com/owner/repo` appears under `benchmarks/`, `src/`, `tests/` or `.kiro/` (341 repositories, extracted by grep and compared case-insensitively); PMPro, Ultimate Member, LearnPress, phpMyFAQ, YesWiki, MediaWiki (including MediaWiki extensions), WP Statistics, froxlor, GoPay, Directorist and Groundhogg by name; repositories over about 150 MB by the GitHub API `size` (153,600 KB); advisories without a fix diff.

Operational rules, carried over from the v2 research (`research-2026-09-26.md`) and fixed before the first advisory was read:
- **In scope** means a web application, CMS, web framework/bundle or plugin whose vulnerable code is reached from HTTP request handling inside the repository. General-purpose libraries and framework APIs whose attacker input only exists in a calling application, developer tools/CLIs, and client-side JavaScript sinks are rejected (they give the analyzer no in-repo source).
- **Fix**: at most 3 commits, or one commit that is plainly about this weakness; a fix buried in a large unrelated squash or release commit is rejected, as is a fix that changes no PHP line (the fixed pin must differ in PHP). A fix commit the advisory does not name may be taken from the release compare or the named file's history, and is then marked `fix_named_by_advisory: false`.
- **One case per repository.** Old vulnerabilities republished in 2026 under an older CVE id are rejected (v2 did the same).
- **Guard-bypass and incomplete-fix advisories are allowed**, with the caveat recorded.
- **At no point was a case chosen or skipped for how easy it would be for this analyzer.** No rule or query of the project was consulted.

### Order and quotas

- **Family quotas** (targeting about 27 candidates): injection 8, output_encoding 4, path 4, untrusted_destination 4, access_control 4, deserialization 3.
- **Passes by family, rarest first**, so that one-case-per-repository does not hand a rare family's only repository to a common family. Rarity was counted from metadata alone (distinct eligible repositories per family after the automatic exclusions, before any advisory text was read): deserialization 1, injection 9, path 10, untrusted_destination 11, access_control 16, output_encoding 21. Within a pass, advisories are taken newest first (by `published_at`); a repository taken in an earlier pass is skipped.
- **Sources (lanes)**, consulted in this order within a pass, and each later lane only for a family still short after the earlier ones:
  - **Lane A** — reviewed GitHub advisories, ecosystem composer, published >= 2026-06-01 (582 records; 386 in the six families). `gh api --paginate "/advisories?ecosystem=composer&type=reviewed&published=>=2026-06-01&sort=published&direction=desc"`.
  - **Lane B** — unreviewed advisories for the family CWEs of injection, path, deserialization and untrusted_destination (5,246 records), kept when a reference is a `github.com/<o>/<r>/(commit|pull|compare)/` link and the GitHub API reports the repository's language as PHP (92 records on 56 PHP repositories). Output_encoding and access_control were not fetched, because lane A filled them.
  - **Lane C** — deserialization only: unreviewed CWE-502 advisories whose text names WordPress (42), each plugin searched on GitHub for a development repository (SVN mirrors do not count, as in v2), plus the non-WordPress CWE-502 records naming a PHP product (9). The Patchstack one-line records ('Unauthenticated PHP Object Injection in X <= v') never name a function and were not examined individually.
  - Lanes B and C were added after lane A left injection 4, path 3 and deserialization 0 against their quotas; the lane rule was fixed then, before any lane-B/C advisory was read.
- **Verification** of every candidate: `gh api repos/O/R/commits/<sha>` for the fixed commit (parents, message, changed files); the vulnerable pin is the fixed commit's (first) parent, except where a short linear chain is noted; `compare/<fixed>...<release tag>` confirms the fixed commit is an ancestor of the first fixed release wherever a tag exists; repository size, licence and default branch from `repos/O/R`.

### Per-candidate notes

#### grav-blueprint-bare-function-rce (injection; code injection (callable allow-list bypass → arbitrary PHP function))
- Repo https://github.com/getgrav/grav (MIT, 34 MB, languages PHP 100%). Lane A. Advisory CVE-2026-75827 / GHSA-f8wv-xp27-6gq7, published 2026-09-17; affected <= 2.0.14; fixed 2.0.15.
- Sink: system/src/Grav/Common/Data/Blueprint.php:455-458 `call_user_func_array($o, $params)` (bare-function dynamic-data provider), gated by `Blueprint::isSafeDynamicCall()` (Blueprint.php:514-536), whose bare-function branch uses only the denylist `Utils::isDangerousFunction()`; twin sink system/src/Grav/Framework/Flex/FlexDirectory.php:936-938 `call_user_func_array($function, $params)`. Source: a blueprint `data-*@` directive naming a bare PHP function (e.g. `error_log`) with attacker parameters, resolved by `Blueprint::init()`. Privilege: authenticated account that can edit pages/blueprint data (per the advisory's root-cause section; verify).
- Fix: The advisory links no commit. Found in the release compare 2.0.14...2.0.15 (14 commits, each security fix labelled): `af31066e` '[security] Gate the blueprint bare-function data directive on a positive allowlist', 1 file (Blueprint.php +11-1). A later commit in the same release, `c51987f5` 'Trust blueprint dynamic-data providers by provenance, not by allowlist', reworks the same gate. Ancestry: parent; ancestor of tag 2.0.15.
- Sites: file paths and function names quoted by the advisory. sink_evidence `call_user_func_array($o, $params)`.
- Benign: fixed pin as fixed-side control; proposed benign change `8661b3b56448` "Deduplicate repeated debugger deprecation traces" (172 lines, CHANGELOG.md, system/src/Grav/Common/Debugger.php, tests/unit/Grav/Common/DebuggerDeprecationsTest.php).
- Caveats: guard bypass: the vulnerable pin already has a denylist check; the enclosing function of the call_user_func_array line is not named by this advisory (sink_evidence is used instead). Confidence: high.

#### backpack-stats-host-header-cmdi (injection; OS command injection)
- Repo https://github.com/Laravel-Backpack/CRUD (MIT, 76 MB, languages PHP 80%, Blade 17%). Lane A. Advisory CVE-2026-54182 / GHSA-mrc5-3mm3-45c5, published 2026-08-20; affected 7.x < 7.0.36 (also 4.1.x < 4.1.72, 5.x < 5.6.2, 6.x < 6.8.13); fixed 7.0.36.
- Sink: `Backpack\CRUD\Stats::makeCurlRequest` builds a shell command and passes it to `exec()`. Source: HTTP `Host` header, on every production request through `BackpackServiceProvider::boot()` (1-in-100 random gate). Privilege: unauthenticated.
- Fix: The advisory links only release tags. The compare 7.0.35...7.0.36 contains exactly one commit, `282ba2a0` 'refactor stats to use guzzle only' (src/Stats.php +6-31), matching the advisory's 'makeCurlRequest was replaced with the Guzzle-based path'. Ancestry: parent; the fixed commit is tag 7.0.36.
- Sites: class and method named by the advisory; the path src/Stats.php follows from the PSR-4 class name and is confirmed only by the fix commit's file list.
- Benign: fixed pin as fixed-side control; proposed benign change `608652b1020b` "fix color display (#5992)" (8 lines, src/resources/views/crud/columns/color.blade.php).
- Caveats: needs exec() and curl available, and a Host header that the web server passes through (the advisory rates AC:H). Confidence: high.

#### winter-filter-numberrange-sqli (injection; SQL injection)
- Repo https://github.com/wintercms/winter (MIT, 68 MB, languages PHP 70%, JavaScript 19%, Less 8%). Lane A. Advisory CVE-2026-32593 / GHSA-m7jc-g4rc-jmvh, published 2026-08-12; affected <= 1.2.12; fixed 1.2.13.
- Sink: `Backend\Widgets\Filter` builds SQL for a `numberrange` scope configured with a `conditions` key. Source: the filter widget's AJAX handler (`numbersFromAjax`, per the advisory title). Privilege: authenticated backend user with access to an affected list view.
- Fix: Advisory workaround names commit `50713de9` 'Use parameter binding for filter scope values in conditions statements' (modules/backend/widgets/Filter.php +64-24, plus a test). Ancestry: parent; ancestor of tag v1.2.13, not of v1.2.12.
- Sites: class `Backend\Widgets\Filter` and `numbersFromAjax` named by the advisory; path confirmed by the fix commit.
- Benign: fixed pin as fixed-side control; proposed benign change `2a342f94ae7c` "Improved Ukrainian translation (#1467)" (46 lines, modules/backend/lang/uk/lang.php).
- Caveats: no built-in view uses the vulnerable scope/config combination: exploitable only with a plugin that registers a numberrange scope with `conditions` (the sink is in core, the configuration is not). Confidence: medium.

#### mantisbt-tokenizer-eval-rce (injection; code injection (eval))

#### qloapps-customermessage-bo-query-sqli (injection; SQL injection)
