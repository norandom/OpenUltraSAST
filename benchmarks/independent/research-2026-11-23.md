#### 1. wp-rtmedia-compare-sqli (PHP+JS, WordPress plugin)
- Repo: https://github.com/rtCamp/rtMedia (default branch `develop`; licence field "none", no licence file at HEAD; the WordPress.org plugin page is the licence source -- not verified).
- Advisory: CVE-2026-16482 (Wordfence, published 2026-09-11, CVSS 7.5, unauthenticated, fixed 4.7.12); GHSA-qjq8-433v-gm7m is the unreviewed mirror.
- Flaw: `RTMediaQuery::query()` (app/main/routers/query/RTMediaQuery.php lines 610-611) copies `$_REQUEST` into the query array when the `rtmedia_shortcode` GET parameter is set and filters top-level keys only. The nested `compare` value reaches `RTMediaModel::get()` (app/helper/RTMediaModel.php lines 101-116 at the vulnerable commit: `$compare = $colvalue['compare']`, `$compare = esc_sql( $compare )`, then `$where .= " AND {$this->table_name}.{$colname} {$compare} ('{$col_val_comapare}')"`). Same pattern in app/helper/db/RTDBModel.php `get()` and in the meta-query branch (line 94).
- Fix `7b0e50fc…` (2026-07-29, "fix(security): validate compare operator against allowlist to prevent SQL injection"): new `RTDBModel::sanitize_sql_compare_operator()` allow-list applied at both sinks; `RTMediaQuery::query()` also drops array-valued request keys.
- Diff seen: yes (3 files: RTMediaModel.php +5/-4, RTDBModel.php +21/-2, RTMediaQuery.php +1/-1).
- Odd: 4.7.11...4.7.12 holds 38 commits with five other security fixes (`223c0baa`, `4f4a805c`, `44c5620b`, `987efeca`, `88e2d111`), so use the commit pair. The fix is sink-side and source-side at once.
- Benign, proposed, to be reviewed at freeze time: `f9c4841054898cf6cf6ad2d984c786ba1efb1a11` ("chore: remove obsolete Codeception acceptance tests"), `1c568936f7f8faa97238cd3bf350300d4592ef0e` ("fix: update dependency versions in package.json").
- Confidence: high.
